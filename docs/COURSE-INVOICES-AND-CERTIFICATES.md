# Course invoices and certificates

## Summary of the existing documents

The PRD describes a multi-vendor invoicing system with Owner and Creator roles. Creators prepare their own invoices for approval; Owners issue invoices and publish immutable revisions. Documents remain private, and customers access one invoice through an email link and OTP. Issued invoices retain their history, payments and receipts. The pilot uses test payments; refunds are deferred.

The architecture separates the TypeScript API from a background worker. PostgreSQL stores tenant data, revision snapshots, audit events and durable jobs. The database design uses tenant isolation and historical invoice snapshots. The API design keeps staff role checks and customer invoice scope on the server. This feature follows those mechanisms.

## Implemented flow

1. Open **Invoices → Prepare Invoice**, choose a customer and catalogue items. Owners can optionally override a line price and enter its discount. Creator inputs continue to use catalogue prices without discounts.
2. Choose **NamasteDev-style course invoice — dark** or **Udemy-style course tax invoice — light**. Classic retail/book and service layouts are also available.
3. Enable **Generate a course certificate with this invoice**. Course layouts enable it initially; it can be turned off. Certificates may also accompany another layout when its items represent a course.
4. Set the learner, course title, certificate date, optional instructor and certificate style. Participation is the default wording; completion is an explicit issuer choice. Learner and course fields default to the selected customer and item names.
5. Use **Preview invoice PDF** or **Preview certificate PDF**. Previews do not issue an invoice or consume quota.
6. Save the draft and use the existing Owner issuance/approval flow. The worker generates the invoice and its certificates from the immutable revision snapshot.
7. Open the issued invoice to download its PDFs. The OTP-protected customer invoice page also lists certificate downloads.
8. To add a certificate later, open an issued invoice and choose **Create course certificate**. Only its Vendor Owner can perform this action. It creates a document linked to the current revision without changing invoice totals, payments or quota.

## Data and API changes

- Migration `005_invoice_templates_certificates.sql` adds invoice document options, the certificate document kind, certificate numbering/indexes and line-level HSN/SAC snapshots.
- `document_options.template` accepts `STANDARD`, `COURSE` (NamasteDev style), `UDEMY` or `SERVICE`.
- Document options include optional order reference, place of supply, shipping address, service dates, notes and up to twenty certificate specifications. Every certificate has a recipient, course, date, style and participation/completion wording.
- `POST /api/v1/invoices/preview-invoice` and `POST /api/v1/invoices/preview-certificate` accept an invoice draft and return a PDF.
- `POST /api/v1/invoices/:id/certificates` accepts certificate details plus a UUID `request_key`. Retrying the same request reuses its job and certificate number; changing its contents requires a new key.
- `GET /api/v1/invoices/:id/documents` lists available documents after the existing staff invoice visibility check.
- Downloads use the existing staff/customer document endpoints. Customer lists show invoice PDFs and certificates for the current revision; historical documents remain stored.
- Shared PDF rendering lives in `packages/documents`. Liberation Sans fonts and their license are included for portable rendering. PDFKit is recorded in the workspace lockfile.
- Certificates requested during draft preparation are generated by the invoice PDF job. Separately requested certificates use an encrypted job payload and audit event. Generation uses stable document identities and uniqueness constraints to prevent duplicate document rows on retries.

## Reference mapping

See `invoices/README.md`. The existing Udemy invoice is also saved as `invoices/Udemy-reference.pdf`. The vendor's business identity is used in generated documents; these are selectable visual styles.

## Setup before use

Using Node.js 22.15 or newer, run `npm install` (or `npm ci`), then `npm run db:migrate` with the existing migration environment configured. Restart the API, web and worker processes. The worker must be running for issued document downloads to become available. Existing issued PDFs are retained; new layouts apply to newly issued revisions.

Development only: no builds, migrations or test suites were run for this change, at the user's request. The selectors and forms were added to the web app; the shared API also accepts these document options from other clients.
